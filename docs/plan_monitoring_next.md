# План: радиомониторинг, следующий этап

Продолжение `plan_monitoring.md`. Выполнены 8.4, 9.5 (частично), 9.7, 10.5, 11.2.

Размеры: **S** — до дня, **M** — 1–3 дня, **L** — больше.

## 8. Измерения

### 8.5 Мощность канала и OBW (M, после 8.1)
**Решение.** Мощность в полосе выбранного демодулятора (интеграл по бинам с поправкой на ENBW). OBW 99% — ширина, содержащая 99% мощности канала. Вывод в `DemodulatorPanel` или строкой под спектром.
**Затронутые файлы.** `DSP/DspUtils` (+ тесты), UI в `RadioMonitorPage` / `DemodulatorPanel`.
**Критерии приёмки.** На синтетическом сигнале известной полосы OBW совпадает ±1 бин.

## 9. Классификатор

### 9.5a Сброс интервала по скачку уровня (S)
Остаток 9.5: адаптивный интервал уже сбрасывается при смене VFO и класса, но не при скачке уровня. Нужен сброс на 100 мс, когда уровень в канале меняется больше чем на N дБ (например, 10 дБ).

### 9.6 Настоящая модель (L, отдельный трек)
Замена `classify()` в скрипте (например, ONNX Runtime). C++ не затрагивает.

## 10. Подавление помех

### 10.3 Шумоподавление (NR) спектральным вычитанием (L)
**Решение.** Overlap-add на FFTW, оценка шума minimum statistics, сглаживание усиления против «музыкального шума». Параметр — сила подавления. FM/NFM/AM/SSB.
**Критерии приёмки.** На записи с шумом измеримый рост SNR без слышимых артефактов.
UI: чекбокс и ползунок через `ParamDesc`, как NB (10.5).

### 10.4 Автоматический notch для SSB/AM (M)
Адаптивный LMS-фильтр против стационарных тонов. Параметры: скорость адаптации, длина фильтра.
UI: как NB (10.5).

## 11. Декодеры

### 11.3 RDS для WFM (L)
**Решение.** Поднесущая 57 кГц (восстановление по пилоту 19 кГц ×3), BPSK 1187.5 бод, дифференциальное декодирование, синхронизация блоков по синдрому, поля PS / RT / PI.
**Ограничение.** `FmModem` работает на ПЧ ~480–500 кГц, затем FIR2 режет до 15 кГц — MPX нужно забирать до FIR2 отдельной ветвью.
**Затронутые файлы.** `DSP/FmModem`, новый `DSP/RdsDecoder.{h,cpp}`, вывод PS/RT в панель.

### 11.4 Внешние цифровые декодеры (M)
**Решение.** Общий `ExternalDecoderController`: звук или I/Q во внешний процесс (dsd-fme, multimon-ng для POCSAG/DTMF/APRS) через stdin или UDP. Позже переиспользовать для классификатора.
